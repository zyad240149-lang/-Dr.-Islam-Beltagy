# التقرير النهائي — ربط نظام عيادة د. إسلام بلتاجي بـ Supabase

تاريخ: 2026-10-26 · المشروع: `jdhnxfhwwszxykizrahb` (eu-west-1, Postgres 17.11)

## A. تقييم المستودع
| البند | الموجود |
|---|---|
| الواجهة | React 18 + TS + Vite 5، react-router 6، عربي RTL، PWA + طابور أوفلاين (IndexedDB) |
| الخادم قبل العمل | لا يوجد — كانت الواجهة شغالة على «خادم وهمي» محلي داخل المتصفح (localStorage) |
| الخادم بعد العمل | Supabase: Postgres + Auth + Storage + Edge Function `api` + pg_cron |
| المصادقة | Supabase Auth (بريد داخلي `<رقم E.164>@clinic.local` + كلمة مرور، الواجهة بتطلب رقم الموبايل) |
| الصلاحيات | جدول `role_permissions` (6 أدوار × المناطق) + `has_perm()/require_perm()` في كل RPC + سياسات RLS على كل جدول |

**ملاحظات معمارية:** الواجهة منقولة من نظام آخر وكانت مصممة لقاعدة بيانات بعينها؛ أسرع وأدق طريق كان تطبيق نفس المخطط (197 هجرة) بعد إزالة أي هوية/بيانات تخص النظام الأصلي، بدل إعادة اختراع 120+ دالة.

## B. ملخص التنفيذ
- **قاعدة البيانات:** 204 هجرة مطبّقة (`000_extensions` + 197 هجرة أساس `001…198` + `900_clinic_setup` + `901_disable_accounting_einvoicing` + `902_security_hardening` + `903_egypt_localization` + `904_egypt_national_id_constraint` + `905_register_link_verification`)، 105 جدول.
  - إصلاحات على هجرات الأساس عشان تشتغل على قاعدة فاضية: `162` (عدّاد رقم الملف = NULL مع جدول فاضي)، `164` (عمود `attendance_since` كان مضاف يدويًا في النظام الأصلي ومش موجود في الهجرات).
  - المنطقة الزمنية لكل الدوال: `Africa/Cairo` (كانت الرياض).
- **900:** بيانات العيادة (جنيه مصري، ضريبة 0، دوام 4–10 م والجمعة إجازة)، 11 خدمة عظام بدل الخدمات القديمة، ملف «د. إسلام بلتاجي»، و4 جداول جديدة:
  `ortho_consultations`, `ortho_imaging`, `ortho_surgeries`, `ortho_fractures` — مفاتيح أجنبية للمريض (حذف متتابع)، قيود (تشخيص/شكوى/منطقة مش فاضية، الجهة والحالة من قائمة محددة، موعد فك الجبس ≥ تاريخ التركيب)، فهارس، RLS، سجل تدقيق `audit_row()`، `created_by` تلقائي من الموظف.
- **901:** إيقاف كل أثر للنظام المحاسبي والفوترة الإلكترونية (تريجرات القيود التلقائية وحراسة فواتير الهيئة) — اتشالوا من الواجهة بطلب العيادة.
- **902:** قفل 6 دوال كانت متاحة للزائر بدون دخول، و`search_path` ثابت لدالة جديدة.
- **903 + 904 (توطين مصر — اكتشفته الاختبارات):** القاعدة كانت رافضة تأكيد أي موعد أو تسجيل حضور لمريض إلا لو معاه **هوية/إقامة سعودية** (10 أرقام تبدأ بـ 1/2) — يعني كل المرضى المصريين كانوا هيتقفلوا. اتغيّر في 23 دالة + قيد الجدول + الواجهة: مصري = **الرقم القومي 14 رقم يبدأ بـ 2/3**، أجنبي = **رقم جواز السفر**. كمان «سعودي/غير سعودي» ← «مصري/أجنبي» في كل النصوص، و«ر.س» ← «ج.م» في رسائل وسجلات الخادم، وبيع منتج لعميل بدون جنسية بقى مسموح (مصري افتراضيًا). القيم المخزّنة `saudi`/`non_saudi` فضلت زي ما هي عشان باقي الدوال ماتتأثرش (saudi = مصري).
- **إصلاح الولاء:** كود الجلسة المجانية كان بيتسعّر من خدمة قديمة اتمسحت (`sv_pt`) فبيرجع لقيمة ثابتة 250 — بقى بسعر جلسة التأهيل `sv_physio` (300)، ومختبَر.
- **Edge Function `api`:** منشورة (`/me`، إدارة حسابات الموظفين، `/register` لإنشاء حساب مريض). بدون دخول ← 401 (مختبَر).
- **حساب المريض (إنشاء حساب + تسجيل دخول):** صفحة `/signup` (اسم ثلاثي بالعربي، موبايل، بريد اختياري، كلمة مرور وتأكيدها) ← `/api/register` بينشئ الحساب وملف المريض (المصدر: الموقع) أو بيربطه بملفه الموجود بنفس الموبايل، وبعدها دخول تلقائي لبوابة المريض `/me`.
- **905 — إثبات ملكية الملف قبل الربط:** لو فيه ملف (أو أكتر — عيلة بموبايل واحد) بنفس الموبايل ومش مربوط بحساب، المريض لازم يكتب **الرقم القومي (أو الجواز) المسجّل في الملف**، والحساب بيتربط بالملف اللي رقمه مطابق. الملف اللي مالوش رقم قومي ← رسالة «كلّم العيادة» بأرقام العيادة ومفيش حساب بيتعمل (الاستقبال يضيف الرقم القومي للملف وبعدها يقدر). 5 محاولات غلط في الساعة على نفس الموبايل ← قفل ساعة. الفحص (`register_link_check`) بيتم قبل إنشاء حساب الدخول، و`register_customer` بيطبّق نفس الشرط تاني؛ الدالتين للخادم بس. نفس الشرط على `/api/google-complete`. الأرقام العربية والمسافات بتتوحّد (`norm_id`). نفس شاشة `/login` للموظفين والمرضى. روابط «تسجيل الدخول» و«إنشاء حساب» و«احجز أونلاين» في صفحة الهبوط.
- **الواجهة:** `src/lib/supabase.ts` و`src/lib/api.ts` بقوا العميل الحقيقي؛ اتمسح الخادم الوهمي (`src/lib/local/`).
  أقسام العظام (`src/ortho/`) اتحولت للقاعدة: الحفظ بيستنى رد الخادم، رسالة النجاح بعد الرد فقط، رسالة الخطأ الحقيقية، حالات تحميل/خطأ مع «إعادة المحاولة»، وأزرار الإضافة/التعديل/الحذف بتظهر حسب الصلاحية (نفس شرط RLS).
  شاشة الدخول اتشال منها صندوق «حساب تجريبي».
- **سكريبتات:** `db-migrate`, `deploy-function`, `create-admin`, `e2e`, `e2e-modules`, `gen-egypt-migration`, `supabase-check`, `inventory` + أدوات مشتركة `_harness.mjs` (راجع `docs/SETUP.md`). `npm run test:e2e` بيشغّل الـ 3 اختبارات (`e2e` + `e2e-modules` + `e2e-patient`).

**بصراحة:** مافيش اختبار «حقل بحقل» لـ 476 حقل و655 زر على الخادم الحقيقي. اللي اتعمل:
- كل الـ 31 صفحة اتفتحت وظهرت بدون أخطاء — **لكن على الخادم الوهمي القديم** قبل التحويل، مش على Supabase.
- بعد التحويل: اختبارات تكامل على مستوى الخادم (113 اختبار) للمسارات الأساسية والأقسام: الباقات والتقسيط، المنتجات والمخزون، الولاء، حضور الموظفين، الرواتب والتارجت.
- **ممنوع (Blocked):** الدخول من المتصفح الآلي — تسجيل الدخول بيبعت كلمة المرور لخادم Supabase (خارج الجهاز)، وده خارج اللي مسموح لي أكتبه في صفحات. **المطلوب منك:** تدخل بنفسك وتلف على الصفحات (أو تسمحلي أعمل حساب اختبار على نسخة staging).

## D. نتائج الاختبارات
- `npx tsc -p . --noEmit` → بدون أخطاء.
- `npm run build` → نجح (`dist/`).
- فحص الحزمة: مفتاح service_role / access token / كلمة مرور المدير **مش موجودين** في `dist/` (المفتاح العام anon بس، وده متوقع).
- `node scripts/e2e.mjs` → **31/31 نجحوا** (آخر تشغيل بعد هجرة 902). التفاصيل في `docs/e2e-results.json` و`docs/REQUIREMENTS_TRACEABILITY.md`:
  - الدخول: رفض كلمة مرور غلط، `/api/me` للمدير، الزائر بدون دخول ما يقراش المرضى.
  - الموظفين: إنشاء استقبال وطبيب، رفض رقم مكرر، رفض كلمة مرور قصيرة، الاستقبال ما يقدرش ينشئ موظفين.
  - المرضى: إضافة + رقم ملف تلقائي + الحفظ الفعلي + البحث.
  - المواعيد: حجز، **رفض الحجز المكرر من الخادم**، رفض خارج الدوام، **حجزين متزامنين → واحد بس ينجح**.
  - الفواتير: فاتورة تلقائية بسعر الخدمة، رفض دفع أكبر من المتبقي، دفعة جزئية، المدفوع/المتبقي/الحالة محسوبين على الخادم.
  - الصلاحيات المالية: الاستقبال ما يشوفش الرواتب ولا إيراد اللوحة، المدير يشوف.
  - العظام: الاستقبال ما يكتبش ولا يحذف تشخيص (قراءة فقط)، الطبيب يكتب ويتسجّل باسمه، رفض تشخيص فاضي، رفض تاريخ فك جبس قبل التركيب، الإضافة متسجلة في سجل التدقيق.
- `node scripts/e2e-modules.mjs` → **82/82 نجحوا** (`docs/e2e-modules-results.json`):
  - **اكتمال بيانات المريض (مصر):** تأكيد موعد لمريض بدون رقم قومي مرفوض، رقم بالشكل السعودي مرفوض، جواز سفر قصير مرفوض، رقم قومي مصري ← التأكيد ينجح، الأجنبي بجواز سفر ملفه مكتمل.
  - **الباقات:** الاستقبال ما يبيعش (المحاسب بيبيع)، الحالة والسعر وعدد الجلسات من الكتالوج، فاتورة تلقائية، +4 نقاط ولاء، حضور جلسة (زيارة مباشرة) والمتبقي يتحسب، جلسة تانية نفس اليوم مرفوضة بدون موافقة المدير، الإلغاء للمدير بس، الفاتورة المدفوع منها مابتتلغيش، النقاط بتتسحب، الحضور على باقة ملغاة مرفوض.
  - **التقسيط:** باقة 4 جلسات بتبدأ «بانتظار الدفع»، الطلب من الاستقبال والموافقة للمدير بس، القسطين نص بنص، طلب تاني مرفوض.
  - **المنتجات:** SKU مكرر وسعر سالب مرفوضين، الطبيب ما يبيعش، الإجمالي بدون ضريبة، **نفس العملية مرتين ماتخصمش مرتين**، بيع فوق المتاح مرفوض، **بيعتين متزامنتين لآخر قطعة → واحدة بس**، الإلغاء للمدير بس ويرجّع الكمية ومرة واحدة، حذف منتج له مبيعات = تعطيل.
  - **الولاء:** الرصيد، الطبيب ما يستبدلش، الاستبدال بكود FREE، **التكرار مابيخصمش مرتين**، الرصيد غير الكافي مرفوض، قيمة الكود = سعر جلسة التأهيل، السجل فيه −30.
  - **حضور الموظفين:** انصراف قبل حضور مرفوض، الحضور مرتين بيحتفظ بأول وقت، الانصراف مرتين مرفوض، التقرير للمدير بس.
  - **الرواتب (على شهر 2020-01 عشان ماتلمسش شهر حقيقي، والاختبار بيتأكد إنه فاضي الأول):** الإعداد للمدير بس، نسبة > 100% مرفوضة، راتب ثابت لطبيب كإداري مرفوض، «تارجتي» = إيراد 1200 من 1000 ← عمولة 10% = 120، الاعتماد بيثبّت المستحقين، صرف الراتب والعمولة، **تكرار الصرف مابيتسجّلش مرتين**، صرف فوق المستحق أو بتاريخ مستقبلي مرفوض، إلغاء اعتماد شهر عليه صرف مرفوض، المالية بتجمع صح، الاستقبال ما يشوفش المالية، الإغلاق، إلغاء صرف مرة واحدة والملغي مابيتحسبش.
- `node scripts/e2e-patient.mjs` → **38/38 نجحوا** (`docs/e2e-patient-results.json`):
  - **إنشاء الحساب:** رفض اسم مش ثلاثي، اسم بحروف إنجليزي، كلمة مرور قصيرة، تأكيد مختلف، موبايل غلط؛ النجاح بيرجّع رقم الملف؛ نفس الرقم مرتين ← 409؛ ملف المريض اتعمل والمصدر «الموقع».
  - **الربط بالرقم القومي (905):** ملف من غير رقم قومي ← «كلّم العيادة» ومفيش حساب دخول اتعمل؛ بعد ما الاستقبال يضيف الرقم: من غير رقم ← بيطلبه، رقم غلط ← مرفوض، الرقم الصح (حتى بأرقام عربية ومسافة) ← اتربط بنفس الملف ومفيش ملف مكرر؛ عيلة بموبايل واحد ← الحساب اتربط بملف صاحب الرقم مش أول ملف؛ 5 محاولات غلط ← قفل حتى بالرقم الصح؛ دالتين الفحص والإنشاء مش متاحين من المتصفح.
  - **الدخول والبوابة:** كلمة مرور غلط مرفوضة، `/api/me` = customer، ملفي، لوحة المريض، الكتالوج، الأوقات المتاحة، **الحجز أونلاين** وظهوره في «مواعيدي» وعند الاستقبال (المصدر: أونلاين)، حجز نفس الوقت مرتين مرفوض.
  - **العزل:** المريض بيشوف ملفه بس، مايشوفش ملف مريض تاني، مايقدرش يستخدم دوال الموظفين ولا يكتب تشخيص ولا يفتح حسابات الموظفين.
- بيانات الاختبار بتتمسح بعد كل تشغيل (الاختبارات بتطبع اللي فضل)؛ القاعدة دلوقتي: مدير واحد + طبيب واحد + الخدمات، صفر مرضى.

| الخطورة | الملاحظة | الحالة |
|---|---|---|
| **حرجة** | مفتاح service_role و access token اتبعتوا في المحادثة | ⚠️ **لازم تعملهم Roll/Revoke** وتحدّث `.env` |
| عالية | ربط الحساب بملف موجود بالموبايل بدون تحقق من ملكية الرقم (أي حد يعرف موبايل مريض كان يقدر يفتح ملفه) | ✅ اتقفلت (905): الربط بالرقم القومي/الجواز المسجّل في الملف + قفل بعد 5 محاولات — مختبَر |

| منخفضة | مفيش تحقق إن صاحب **الحساب الجديد** (من غير ملف سابق) هو صاحب الموبايل | المريض بيشوف ملفه الجديد بس؛ لو صاحب الرقم الحقيقي جه بعدين، الاستقبال يتعامل من «الحسابات الأونلاين». الحل الكامل: كود SMS |

| عالية | دوال للزائر بدون دخول (`public_catalog`, `doctor_day_slots`, `busy_slots`, push…) | ✅ اتقفلت (902) — مختبَر: 401 |
| متوسطة | حماية كلمات المرور المسرّبة (HaveIBeenPwned) | ❌ تحتاج خطة Supabase Pro (رد 402) |
| متوسطة | 256 دالة SECURITY DEFINER قابلة للتنفيذ للمستخدم المسجّل | بالتصميم — كل دالة بتنادي `require_perm()` أولًا؛ مراجعة كل واحدة يدويًا لسه ماتمتش |
| منخفضة | `pg_net` في schema `public` | متروك (نقله بيكسر دوال الإشعارات) |
| منخفضة | دالتين محاسبيتين بدون `search_path` ثابت | غير مستخدمتين بعد 901 |
| معلومة | 7 جداول RLS بدون سياسات (counters, push_config, zatca_config…) | مقصود — للخادم فقط |
| منخفضة | الطابور الأوفلاين بيخزن بيانات مرضى في IndexedDB على الجهاز | بيتمسح عند تسجيل الخروج العادي؛ تجنّب الأجهزة المشتركة |

## F. قاعدة البيانات وسلامة البيانات
